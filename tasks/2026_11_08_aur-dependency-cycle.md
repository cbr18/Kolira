# Реальный цикл зависимостей из AUR

**Статус:** DONE 2026-11-26 (реальный цикл AUR выполнен в изоляции). Заведено по
запросу пользователя.

Продолжение проверки [управления зависимостями](2026_11_07_dependency-management.md):
цикл обычного пакета через pacman проверен, реальная сборка из AUR теперь тоже
выполнена (см. «Результат»).

## Требования

1. В чистом изолированном Arch Linux окружении с обычным пользователем и
   поддерживаемым AUR helper выполнить реальную загрузку, сборку и установку
   зависимости темы. Записать пакет, версии окружения/helper и журнал операций.
2. Проверить цикл через менеджер: установить → проверить пакет, ресурс и реестр
   → удалить → подтвердить отсутствие → переустановить. Повторная установка
   не создаёт дубликатов и не присваивает владение существовавшему ранее пакету.
3. Проверить общий пакет двух тем, предупреждение о затронутых темах, уже
   установленный внешний пакет и восстановление состояния после частичного сбоя.
4. Проверить ошибку загрузки/сборки, отсутствие helper, ожидание ввода/пароля,
   отмену и повторную попытку. GUI остаётся отзывчивым, ошибки видны; выполняющаяся
   привилегированная транзакция завершается безопасно.
5. Проверить учёт источника `aur`, доступность установленного ресурса и политики
   `ask/always/never` для системных пакетов. Исправления выполнять в существующем
   Rust-исполнитере и реестре; Python остаётся адаптером GUI.

## Результат (2026-11-26)

- Окружение: одноразовый контейнер `archlinux:latest`, обычный пользователь
  `builder`, реальный AUR-helper **yay 13.1.0** (собран из AUR как `yay-bin`).
- Зависимость: AUR-пакет **paru-bin 2.2.1-1** (собран из AUR, установлен
  `pacman -Q`, затем удалён и переустановлен).
- Цикл: `install → list → remove` (без `--confirm-shared` падает на общей теме) →
  `remove --confirm-shared` → `install` → `reinstall --confirm-shared` →
  `remove --confirm-shared`; в реестре ровно один ресурс (дубликатов нет).
- Команды: `docker build -f tests/e2e/Dockerfile.aur -t kolira-aur-test tests/e2e`
  и `docker run --rm -v "$PWD:/src:ro" kolira-aur-test`.
- Доказательства: артефакты сборки AUR (`paru-bin-2.2.1-1-x86_64.pkg.tar.zst`,
  PKGBUILD, yay cache) и журнал `package-terminal.log` с `installing/reinstalling/
  removing paru-bin`; `result.json` → `"passed": true`.
- Нюанс harness: в контейнере нет человека, поэтому подставной терминал добавляет
  `--noconfirm` к `yay`/`paru`; пакет при этом собирается и ставится по-настоящему
  (проверка через `pacman -Q`, а не по коду возврата).

Пакеты проверять в одноразовом контейнере/VM. Подставные команды и нулевой
exit code без проверки установки не считаются выполненным реальным циклом.

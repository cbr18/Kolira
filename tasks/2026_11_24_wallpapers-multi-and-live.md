# Обои: несколько изображений на тему и живые обои

**Статус:** TODO (2026-11-24). Крупная задача, требует доработки формата темы,
ядра применения и GUI. [Контекст формата](../docs/THEMES.md),
[текущий модуль обоев](../gui/qt-app/src/core/rust_core/src/wallpaper.rs).

## Суть

Сейчас тема хранит **одно** изображение обоев (`theme.json` → `wallpaper:
"wallpaper/<file>"`, один файл `wallpaper/source`) и применяет его **на все
мониторы сразу** через `plasma-apply-wallpaperimage`. Поддерживается только
плагин `org.kde.image`. Этого мало для реального использования:

1. Одна тема не может задать **несколько обоев** (например, по одному на монитор
   или набор для слайд-шоу).
2. Нет поддержки **живых обоев** (POTD, slideshow, видео/PBR-плагины, сторонние
   вроде `org.kde.wallpaper.*`), хотя Plasma их умеет.

Задача — расширить модель обоев в теме и их применение, сохранив существующие
гарантии (appearance-only, журнал отката, XDG-переносимость, проверка путей).

## Направление 1. Несколько обоев на тему

- **Формат:** вместо одиночного `wallpaper` — коллекция изображений с
  назначением. Варианты назначения:
  - **по монитору/экрану** (`lastScreen`, как уже делается для панелей в
    `layout.rs`);
  - **набор для слайд-шоу** (упорядоченный список файлов);
  - **fallback** (одно изображение по умолчанию, если монитор не сопоставлен).
  Обратная совместимость: старый `wallpaper: "wallpaper/<file>"` читается как
  один элемент с fallback-назначением.
- **Snapshot:** тема кладёт несколько файлов в `wallpaper/` и описывает их
  назначение в `theme.json` (по образцу существующего маппинга `assets[]`).
- **Apply:** раскладывает изображения по-desktop/по-монитору через Plasma
  (не `plasma-apply-wallpaperimage` на всё, а адресная установка по
  containment), слайд-шоу — через `org.kde.slideshow` с нужным списком.
- **Undo/журнал:** возврат каждого монитора к прежнему плагину/изображению
  (расширить `wallpaper.rs` + `operation.rs`, где уже есть per-desktop учёт).
- **GUI:** выбор нескольких обоев, привязка к монитору/набору; расширить
  раздел «Обои» и сводку применения.
- **Per-screen применение** попутно закрывает пункт из
  [ROADMAP](../docs/ROADMAP.md) «одни обои на все мониторы».

## Направление 2. Живые обои (провайдеры)

- **Плагины обоев Plasma:** научить тему хранить и применять не только
  `org.kde.image`, но и другие плагины:
  - встроенные: `org.kde.slideshow`, `org.kde.potd`;
  - видео/PBR: `org.kde.wallpaper.*` сторонних пакетов;
  - их настройки (цвета/скорость/источник) как appearance-данные.
- **Провайдеры живых обоев:** подключить внешние источники (например, Plasma
  Wallpaper Engine, mpvpaper, `wallpaper-engine`-совместимые), по аналогии с
  системой зависимостей (`deps.rs`): плагин/пакет = зависимость с источником
  установки (KDE Store / pacman / AUR / Git).
- **Границы:** исполняемый контент живых обоев (скрипты, бинарники) **не
  переносится** внутри темы (как и Spicetify theme scripts) — только
  appearance-ссылки и настройки; установка плагина — через зависимости.
  Проверять пути/происхождение так же строго, как `assets[]`.
- **Безопасность/производительность:** живые обои могут грузить CPU/GPU и
  выполнять код — применение по явному выбору пользователя, с предупреждением, без
  авто-включения при простом применении чужой темы.

## Требуется доработка (что затрагивает)

1. **Формат `theme.json` (`theme.rs`):** структура обоев (одно → коллекция с
   назначением), схема `kolira/theme@3` или обратно-совместимое расширение
   `@2` с дефолтами; миграция старых тем (`migrate`).
2. **Ядро обоев (`wallpaper.rs`):** адресная (per-screen/per-desktop) установка
   вместо глобального `plasma-apply-wallpaperimage`; поддержка нескольких
   плагинов и их настроек; слайд-шоу.
3. **Применение/откат (`profile.rs`, `operation.rs`):** расширить снимок и
   журнал обоев (несколько файлов, несколько desktop, настройки плагина),
   сохранив before/after и проверку личных правок.
4. **Зависимости (`deps.rs`):** новые kinds для плагинов/провайдеров живых обоев
   с источниками установки.
5. **Превью (`preview.rs`, `change_plan.rs`):** план должен показывать
   несколько файлов/desktop и смену плагина.
6. **Экспорт/импорт (`share.rs`):** несколько файлов обоев, ссылки на плагины,
   per-screen данные; проверка путей и размеров.
7. **GUI (`qml/`, `core/cli_core.py`):** выбор нескольких обоев, привязка к
   монитору, настройки живых обоев, сводка применения.
8. **Проверки:** `lint`/`check` — существование файлов обоев, доступность
   плагинов, контраст не применим (это изображение), но пути/ассеты — да.

## Приёмка (высокоуровнево)

- [ ] Тема хранит и применяет несколько обоев с назначением (по монитору и/или
      набор-слайд-шоу); старые одно-обойные темы читаются без миграции вручную.
- [ ] Применение раскладывает обои адресно (per-screen), возврат восстанавливает
      прежний плагин/изображение каждого desktop.
- [ ] Поддержан хотя бы один живой/сменный плагин (slideshow/potd) и/или внешний
      провайдер через зависимости.
- [ ] Живые обои не включаются неявно при чужом apply; исполняемый контент не
      переносится в теме.
- [ ] Экспорт/импорт, превью, зависимости, GUI и журнал покрывают новый формат.
- [ ] Rust/Python/shell тесты; документация (`THEMES.md`, `CURRENT_APP.md`,
      `ROADMAP.md`, `CHANGELOG.md`) обновлена.

## Границы / риски

- **Не атомарно с рабочим столом** — как и текущий apply (внешние плагины,
  D-Bus); живые обои могут выполнять код и грузить ресурсы вне нашего контроля.
- **Портируемость** живых обоев ограничена: бинарный/исполняемый контент не
  переносится, только ссылки и настройки → зависимость.
- **Тестирование на нескольких мониторах** требует реальной Plasma (Docker-сценарий
  friend-in-container подходит частично; per-screen картинки — только живьём).
- Большой объём: затрагивает формат, ядро, apply/undo, deps, export/import, GUI.
  Рекомендуется разбить на подэтапы (сначала много картинок per-screen, затем
  слайд-шоу, затем внешние провайдеры), но вести как одну задачу.

## Связанные идеи (не блокируют)

- Цветовые обои «под тему» (генерация/подбор изображения по палитре) — часть
  направления 1 (набор обоев) или отдельная карточка; здесь отмечена как
  возможное расширение, не как обязательный элемент.
- Управление библиотекой обоев, источники обоев — отложены пользователем ранее.

# Доработка MCP, инструкции агентам и аудит полноты ядра

**Статус:** DONE (2026-11-09), в пределах записанной ниже проверки. Заведено по запросу пользователя.
Выполнен предварительный аудит кодовой базы и исправлены подтверждённые ошибки
обработки запросов/имени MCP. Добавлены основной offline-сценарий, матрица полноты и доставка инструкций;
итоговые проверки и ограничения перечислены в конце карточки. Полный перенос оставшейся логики в Rust
[завершён и проверен](../plans/2026_11_08_single-core-completion.md);
этот перенос закрыл A01; остальные пункты данной задачи реализованы отдельно
и проверены в перечисленных ниже границах.

## Цель

Агент, запущенный из пользовательского каталога тем, получает актуальное описание
формата и доступных операций и может быстро создать, проверить и сохранить
новую тему через поддерживаемый интерфейс. MCP и документация соответствуют
фактическому Rust-ядру; недостающий функционал выявлен и явно учтён.

## 1. Аудит полноты Rust core / CLI / MCP

1. Составить матрицу «пользовательский сценарий → Rust API → CLI → GUI/MCP →
   тесты и ограничения». Сверить текущий код с актуальными требованиями; старые
   незакрытые чекбоксы ТЗ не считать автоматически открытыми задачами.
2. Проверить создание/копирование/сохранение/редактирование тем, палитры и
   генераторы, выбор установленных компонентов, ресурсы и зависимости,
   validate/check/diff, применение, импорт/экспорт, резервные копии/восстановление,
   настройки и реестры. Новые запланированные возможности пометить отдельно
   со ссылками на карточки, не объявляя их уже реализованными.
3. Для каждой возможности отметить: реализовано и проверено / частично /
   отсутствует / доступно только через конкретный интерфейс. Проверять реальное
   выполнение и возвращаемые данные, а не только наличие функции или команды.
4. Проверить соблюдение единого ядра: бизнес-логика и мутации — Rust;
   Python/MCP — адаптеры. Найти дублирование и операции, для которых агенту
   приходится обходить core ручными правками или внешними скриптами.
5. Результат сохранить в документе аудита с доказательствами и приоритетами.
   Необходимые для цельного агентского сценария пробелы включить в план этой
   задачи; остальные оформить отдельными карточками и связать с результатом.

## 2. Доработка MCP

1. Сверить `mcp/theme_profile_mcp.py` и `docs/MCP.md` с текущими командами и
   контрактами. Устранить устаревшие описания, неоднозначные названия, аргументы
   и ответы. Read-only, подготовка и реальные мутации должны быть различимы.
2. Обеспечить последовательный сценарий: узнать возможности → прочитать схему
   темы и установленные компоненты → выбрать/создать палитру → подготовить тему
   → проверить зависимости и содержимое → сохранить/экспортировать → явно применить.
   Подготовка и проверка не должны незаметно менять живое оформление.
3. Сделать контракты пригодными для агента: полные схемы входов/ответов,
   структурированные ошибки с понятным следующим действием, стабильные id,
   явные ограничения и побочные эффекты. Долгие операции должны иметь прогресс,
   статус, отмену и проверяемый итог, используя существующий Rust-исполнитель.
4. Проверить запуск MCP при произвольном cwd, особенно из установленного
   пользовательского каталога тем. Инструкция подключения не должна предполагать,
   что агент находится в checkout репозитория. Предусмотреть документированный
   CLI-сценарий, если MCP у клиента не подключён.
5. Проверить протокол stdio, инициализацию, список инструментов, невалидные
   аргументы, отсутствующий CLI, таймауты и частичные сбои. Диагностика не должна
   повреждать протокольный stdout; успех требует фактической проверки результата.

## 3. Инструкции в пользовательском каталоге тем

1. Подготовить канонический `AGENTS.md` для
   `$XDG_CONFIG_HOME/kde-theme-profile/themes/` и определить нужные аналоги
   (`CLAUDE.md` и другие) по реально поддерживаемым клиентам. Использовать
   общий источник и поддерживаемые ссылки/подключения, чтобы тексты не расходились.
2. Описать архитектуру, XDG-пути, формат `theme.json` и структуры темы, правила
   имён, палитры, ресурсов/лицензий и зависимостей. Добавить короткий рабочий
   рецепт новой темы, точные MCP/CLI-примеры и способы проверки результата.
3. Явно описать границы: снимки read-only в Inspector, личные настройки и
   раскладка сохраняются, fastfetch и меню запуска не тематизируются, живое
   применение выполняется явно, конфиги не редактируются в обход core.
   Уточнить фактическое действие `KTM_THEME_NO_APPLY=1`: не представлять его
   гарантией отсутствия любых файловых изменений.
4. Источник инструкций хранить в kit; доставку и обновление выполнять штатным
   установщиком/Rust-командой, сохраняя пользовательские дополнения и права.
   Описать версию, безопасное обновление изменённых инструкций и резервную копию.
5. Эти файлы — метаданные каталога: они не появляются как темы и не попадают
   в экспортируемые пакеты. Импорт чужой темы не должен заменять корневые
   инструкции или превращать её содержимое в доверенные правила для агента.
6. Проверить обнаружение инструкций при запуске из корня `themes/` и вложенной
   папки темы на выбранных клиентах. Зафиксировать ограничения обнаружения:
   наличие файла само по себе не гарантирует чтение любым агентом.

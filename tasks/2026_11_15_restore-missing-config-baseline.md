# Возврат к своей теме, в которой нет части конфигов

Статус: DONE — 2026-11-15.

Запрос пользователя: применение не должно ломать настройки; цепочка своя тема
→ другая → своя должна возвращать исходное состояние, в том числе если в своей
теме нет конфига приложения. Это уточнение заменяет прежнее правило сброса
отсутствующих файлов к стандартным значениям.

## Воспроизведено

Новые CLI/preview-регрессии на исходном main падали: первое применение пустой
темы удаляло workbench.colorTheme, а после другой темы старое значение не
восстанавливалось. Журнал хранил originals для Whole/некоторых KWin-блоков,
но не для смешанных INI/JSONC. plan_reset затем удалял даже восстановленные
значения и пользовательские файлы с именами kolira*.

## Реализация

- Журнал сохраняет фактические before/after для файлов, ссылок, каталогов и
  удалений; содержимое хранится отдельными проверяемыми SHA-256 blobs (0600,
  каталог 0700). Ошибки чтения не превращаются в пустой журнал/молчаливую потерю
  baseline. Старые created/replaced/blocks/prefs читаются для совместимости.
- Отсутствующий файл в следующей теме оставляет результат отмены предыдущей
  темы; произвольного reset к defaults и удаления файлов по префиксу нет.
- Неизменённое с момента Apply возвращается побайтно с исходными правами.
  JSONC восстанавливается по позициям значений, INI — по ключам. Поздние личные
  значения/комментарии остаются; вложенные JSON-объекты и списки откатывают только
  изменения темы. В host-конфигах обратные точные блоки строк применяются только
  при однозначном совпадении; спорные правки сохраняются.
- Семейство шрифта возвращается с сохранением позднего пользовательского размера.
  Сохраняются исходные пустые каталоги и поздние изменения прав доступа.
- Созданные темой include/prompt-файлы удаляются при возврате исходного host;
  если личная правка host всё ещё ссылается на них, файлы сохраняются.
- Запись ресурсов через перенаправляющий каталог-симлинк отклоняется до
  изменения live-файлов; безопасные симлинки самого ресурса и XDG-контейнеров
  сохраняют предусмотренную поддержку.
- Файлы докатчика (Discord, Konsole, Ghostty, Cava, Firefox, редакторский кэш)
  участвуют в таком же возврате. Повторные циклы проверены отдельно.
- GSettings хранит состояние после Apply для проверки поздних ручных изменений.
  GTK без конфига в следующей теме не перекрывает возвращённый runtime baseline.
  KWin/Qt перезагружаются по эффективному восстановленному конфигу, а не пустому
  исходнику темы; runtime-перезагрузка эффектов не пишет незаявленные флаги.
- Без обоев в следующей теме возвращаются исходные обои. Только явный
  --keep-wallpaper сохраняет текущие изображение и файл, даже если он был создан
  предыдущей темой. Пути восстановленных обоев включены в журнал и recovery.

## Границы

Старый журнал не может задним числом дать значения, которые прежний код не
сохранил. Его доступные записи используются; полные pre-apply backups и история
остаются для явного восстановления старых операций. Новый контракт гарантируется
данными нового журнала. Browser prefs могут требовать перезапуска браузера:
prefs.js не редактируется, обратные значения записываются в user.js.
Обновление кода не означает применение/восстановление оформления хоста.

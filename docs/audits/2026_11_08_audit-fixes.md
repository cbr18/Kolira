## Сохранённое ожидаемое поведение

- Все шесть комплектных тем импортируются и применяются при
  `KTM_THEME_NO_APPLY=1`; посторонний конфиг остаётся неизменным.
- Допустимый ресурс восстанавливается с прежним pre-apply backup. Работают
  XDG_DATA_HOME и перенос самого контейнера ресурсов через symlink; ссылки
  ниже контейнера не используются для перенаправления записей.
- Сохраняются успешные Apply/Undo/Revert, JSONC, политики зависимостей,
  исключение fastfetch/меню запуска и формат тем — проверяются прежним набором.
- Ошибка Inspector теперь намеренно возвращает неуспех и сохраняет staging.
  Это исправленный контракт отказа, а не изменение успешного сценария.

Удалены семь внутренних функций без ссылок, неиспользуемые импорты/локальные
переменные и повторный импорт. Публичный метод протокола и активные writers
сохранены. Выбранные Ruff-проверки F401/F811/F821/F841 проходят без замечаний.

В CI Python offscreen tests больше не `continue-on-error`; в Rust job добавлены
installer/CLI regressions и shellcheck. Сама конфигурация GitHub Actions изменена,
но удалённый запуск CI этой работой не выполнялся.

## Оставшаяся архитектурная работа

A02 исправлена на уровне обязательных локально проверенных наборов и настройки CI.
A01 **не устранена полностью**: перенос действующих Python-мутаций и реестра
в Rust требует переключения контрактов и проверки паритета по операциям.
Подготовлен [план](../../plans/2026_11_08_single-core-completion.md), исполнение
остаётся в [задаче ядра/MCP](../../tasks/2026_11_08_mcp-agent-workflow-core-audit.md).
Удаление этих веток как «мёртвого кода» сломало бы существующие сценарии.

Общая сериализация/rollback apply, история, расписание и агентский workflow не
реализовывались вместо исправлений. Живая Plasma, реальные сетевые установки,
AUR и восстановление после аварии не проверены; текущий результат этого не обещает.

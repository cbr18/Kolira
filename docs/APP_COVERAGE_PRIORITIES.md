# Приложение к roadmap: приоритеты покрытия приложений

Дата проверки: **2026-11-16**. Статус: очередь с приоритетом Apply без ручного выбора темы; файловые адаптеры партий P0 № 1–7, 9–24, 26–29 реализованы в пределах
[контракта и runtime-ограничений](APPLICATIONS.md). Остальные строки — план; файл ресурса и ручной выбор не считаются готовой автоматической интеграцией. Основной [roadmap](ROADMAP.md), [план реализации](../plans/2026_11_15_app-coverage-expansion.md),
[аудит файлов](audits/2026_11_15_app-coverage-files.md), [задача](../tasks/2026_11_15_app-coverage-expansion.md).

## Как определён порядок

1. **P0 — установленные у пользователя**: сначала их пробелы и надёжность
   имеющихся адаптеров. Пакеты проверены через `pacman -Qq`, исполняемые файлы —
   через PATH, дополнительно desktop entries и `flatpak list --app`.
   Установка не доказывает частоту использования; внутри P0 — порядок реализации
   по видимости пробела и возможности использовать общий адаптер, а не статистика
   личной активности. История запуска и содержимое личных конфигов не собирались.
2. **P1 — повторяющиеся Linux/ricing-сценарии**: редакторы, терминалы,
   shell/TUI, лаунчеры, браузеры и музыка. Основание — распространённость сценария в Linux,
   наличие тем и настроек оформления, а также полезность общей
   палитры для ежедневного интерфейса. Один порт темы — сигнал наличия
   экосистемы, не доказательство большой аудитории.
3. **P2 — специализированные сценарии и альтернативные клиенты**: графика,
   офисные/почтовые альтернативы, отдельные медиаплееры и новые IDE. Для них
   сохраняется явный порядок, но ниже основной ricing-очереди.
4. **P3 — остальные кандидаты каталога**: равный низкий приоритет до появления
   запроса, установки или сигнала спроса. Каждая запись исходного каталога учтена.

Это **качественная продуктовая оценка**, а не измеренная доля пользователей Linux.
Сводной статистики установок для всех этих приложений нет. Наличие в дистрибутиве,
нескольких dotfiles и theme-каталогах рассматривается как несколько разных
сигналов; число упоминаний не превращается в процент аудитории. Соседние места
в одной группе допускают перестановку после пользовательской обратной связи.
GitHub stars остаются дополнительной справкой при близких сигналах спроса,
не определяют группу и не сравниваются между зеркалом, монорепозиторием и IDE.

Автоматические сценарии P0 идут раньше P1/P2/P3. Сценарии с ручным выбором/настройкой
вынесены в P4 в самый конец независимо от установки. Номера исходных строк
сохранены для ссылок из задач, это не новый сквозной рейтинг.

Критерий готовности: Apply меняет оформление сразу либо после обычного
перезапуска приложения — **перезапуск допустим**, по уточнению пользователя.
Ручной выбор темы, импорт файла, сброс или дополнительная настройка после Apply
означают **РУЧНОЕ / P4**. Перезапуск отмечается отдельно и сам по себе не снижает
приоритет. Одноразовые CLI читают палитру при следующем обычном вызове команды.
Первичная установка dependencies и подключение опциональных plugins описываются
отдельно; наличие такого plugin не предполагается автоматически.
Не завершать редакторы, звонки, игры или проигрыватели ради видимости автоматики. Внутри каждого приложения сохраняются требования
preview, only-appearance и безопасного возврата по before/after. Большой риск
формата означает предварительное исследование этого приложения, а не разрешение
перезаписать его полный конфиг. Для всех адаптеров действует общий контракт
из этапа 0 плана. Ранее исключённые программы отмечены отдельно.

## Как читать таблицы

«Доработка» означает существующую поддержку Kolira: сначала проверить пробелы
и возврат исходного состояния. «Новый адаптер» — запланированная работа, а не
уже доступная возможность. Наличие файла темы само по себе не означает её
включение в работающем приложении. Все пути и ограничения описаны в
[карте файлов](audits/2026_11_15_app-coverage-files.md).

## P4. Хвост очереди: ручной выбор/настройка или неподтверждённое применение

Перенесено по решению пользователя 2026-11-16. Эти адаптеры сохраняют свои
ресурсы и регрессии возврата, но **не считаются завершённой автоматизацией**.
До возвращения в основную очередь нужен native Apply → обновление клиента
сразу или после допустимого перезапуска → возврат без ручного выбора/сброса.
Перезапуск сам по себе не причина для P4.

«АВТО НЕ ПОДТВЕРЖДЕНО» означает пробел проверки, а не доказанную поломку.
Такие интеграции тоже временно находятся в хвосте: до проверки Apply/возврата их нельзя
обещать как автоматические. При проверке допустим перезапуск клиента. Новые CLI-вызовы lsd/Glow и запуск Wofi не требуют
дополнительной настройки и остаются отдельными сценариями основной очереди.
Автоперезапуск с потерей звонка, документа или игры не является решением.

# Просмотр изменений перед Apply

Ручное применение из главного окна, страницы сохранённой темы и трея открывает
«Просмотр изменений темы». Асинхронный Rust-расчёт показывает создаваемые,
изменяемые и удаляемые файлы, построчный diff, сбросы предыдущей темы,
недостающие компоненты/зависимости, изменения GSettings и действия для приложений.
Можно оставить текущие обои, установить зависимости отдельным шагом или
сохранить текущее оформление под новым именем. После этих действий просмотр
пересчитывается. Установка зависимостей сама тему не применяет.

Просмотр и его отмена не меняют живые конфиги, не создают бэкап применения и не
устанавливают зависимости. Для согласованного чтения используется общая блокировка;
текстовые сравнения создают приватные временные файлы. «Сохранить текущее» —
отдельная явная запись: обычное сохранение темы, включая маркер активного профиля
и разделение поддерживаемых конфигов на личную и тематическую части. Существующая
тема при этом не перезаписывается. Отмена следующего Apply сохранённую тему не удаляет.

## Подтверждение и ядро

`change_plan.rs` хранит виртуальные состояния файлов. Restore, сброс старого
журнала, Konsole, KWin, обои и сохраняемые значения используют одни функции
планирования для предварительного отчёта и реальной записи. Старые снимки
с `theme-bundle.json` учитывают поля и адаптеры приложений. Пакеты применяют всё
описанное в них; для старых снимков GUI учитывает выбор компонентов в настройках.
Пользовательские компоненты восстанавливают целые файлы — диалог предупреждает об этом.

Токен связывает подтверждение с источником темы, входными файлами/правами,
настройками, выбранными компонентами, обоями, доступностью зависимостей и
результатом расчёта. Перед первой записью ядро повторно проверяет токен и
подготовленную копию источника под блокировкой. Изменение состояния возвращает
`PREVIEW_STALE`: GUI открывает обновлённый просмотр и ждёт нового подтверждения.
Автоматического повтора применения нет. Внешние редакторы не подчиняются блокировке;
это проверка состояния перед записью, а не транзакция со всем рабочим столом.

Подтверждённый Apply не устанавливает зависимости автоматически. Если они нужны,
их устанавливают отдельной операцией, затем получают новый токен. Откат и
обработка прерываний остаются в [защите применения](APPLY_PROTECTION.md).
Старое сохранённое `confirm_before_apply` читается для совместимости, но больше
не отключает просмотр; переключатель убран из настроек.

## CLI и API

```bash
kolira preview Paper --json
kolira preview Paper --keep-wallpaper --json
kolira apply Paper --keep-wallpaper --preview-token=TOKEN
```

Параметры Apply должны совпадать с просмотром. Для старых снимков поддерживается
`--components=kwin` (используйте действительные ID из `components`).
Обычный CLI Apply без токена сохраняет прежний сценарий без интерактивного просмотра.

JSON API v1: `profile.preview` принимает `name`, `keep_wallpaper`, `components`,
`use_settings`; возвращает `token`, `source_digest`, `files`, `file_count`,
`missing`, `dependencies`, `actions`, `runtime_changes`, `kept_fields`,
`custom_components`, `keep_wallpaper`, `components`. У файлов есть операция,
причины, diff/признак сокращения, SHA-256/размеры, права и цели ссылок.
`profile.apply` принимает `preview_token`; `profile.save_before_apply` — новое
имя `name`. MCP: `preview_profile`, затем `apply_profile` с `previewToken`.

## Границы

Текстовый diff ограничен суммой 1 MiB входа и 1500 строками на файл; двоичные
данные показываются размерами, права/ссылки отдельно. Токен охватывает полные
данные независимо от сокращённого текста. Сравнение не запускает Plasma и
приложения: создаваемые ими кэши, вычисляемый Plasma акцент обоев и последующая
нормализация конфигов внешними утилитами не являются гарантированным построчным
результатом. Необходимый перезапуск Plasma указан в диалоге; действия для других
приложений определяются по реально планируемым изменениям.

Проверены соответствие SHA-256 после Apply для всех семи комплектных тем (включая Minecraft Overworld Dark) в
изолированном HOME с `KTM_THEME_NO_APPLY=1`, старые снимки, журнал предыдущей темы,
JSONC, отсутствие зависимостей, сохранение обоев и отказ по устаревшему токену.
Это не проверка реальной смены оформления Plasma внешними hooks.

## Раскладка просмотра

Метаданные, виртуализированные файлы и завершающие опции/сохранение текущей темы
входят в один вертикальный ListView. Внешний вертикальный ScrollView больше
не дублирует его; отдельный скролл остаётся только у раскрытого кода diff.
Полоса занимает канал вне строк, доступны последний файл и все опции даже
в низком окне. Счётчик файлов использует русские множественные формы. Контракт
просмотра/отмены/подтверждения не изменён.

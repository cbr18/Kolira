# Переключение тем по расписанию

Расписание исполняет Rust CLI в пользовательской Plasma-сессии. Окно GUI может
быть закрыто. Правила и результаты сохраняются атомарно в
`$XDG_CONFIG_HOME/kolira/schedule.json` (по умолчанию
`~/.config/kolira/schedule.json`).

## Управление

В GUI: «Расписание тем» в меню. Выберите тему, время `HH:MM`, дни недели,
сохраните правило и включите расписание. Включение правила и всего исполнителя
раздельное. Страница показывает следующее время и итог предыдущего события.

CLI:

```sh
kolira schedule put '{"id":"morning","theme":"Paper","time":"08:00","days":[1,2,3,4,5],"enabled":true,"keep_wallpaper":false}'
kolira schedule list
kolira schedule enable
kolira schedule disable
kolira schedule delete morning
```

JSON API v1: `schedule.list`, `schedule.put` (`rule`), `schedule.delete` (`id`),
`schedule.enable` (`enabled`). MCP предоставляет соответствующие инструменты.
`kolira schedule tick` однократно обрабатывает текущую минуту;
`kolira schedule daemon` — исполнитель с проверкой каждые 10 секунд.

## Время и конфликты

- Локальное время системы, ISO-дни: понедельник = 1, воскресенье = 7.
- Сон, отсутствие сессии и пропущенное время не вызывают догоняющее применение.
  После запуска или задержки процесса более 30 секунд текущая неполная минута
  пропускается целиком.
- При переводе часов вперёд несуществующее время пропускается; при переводе назад
  одно локальное событие выполняется один раз. Смена часового пояса меняет
  последующие локальные времена. Сохранённая отметка события предотвращает
  повторение уже обработанного события и более ранних дат.
- При одинаковом времени приоритет имеет первое правило по ID (порядок строк);
  остальные получают пропуск. Ручная операция не прерывается: занятая глобальная
  блокировка оформления означает пропуск события, без очереди повторного apply.
- Событие записывается **до** применения. После аварии остаётся `claimed` или
  прерванная операция в аудите; автоматического повтора нет. Восстановление
  выполняется обычным механизмом защиты применения.
- Отключение/изменение правил влияет на будущие события; уже принятое событие
  может завершить текущую транзакцию. Удаление темы не переназначает правило:
  следующее событие запишет понятную ошибку.

## Фоновое выполнение

Включение создаёт XDG autostart-файл
`$XDG_CONFIG_HOME/autostart/kolira-schedule.desktop` с `OnlyShowIn=KDE;`
и запускает исполнитель для текущей сессии. Это обычный desktop entry без bash
и без системной службы; механизм описан в
[XDG Autostart Specification](https://specifications.freedesktop.org/autostart/0.5/).
Одновременно работает один исполнитель (файловая блокировка). Он завершается
после отключения расписания, удаления CLI или завершения D-Bus сессии.
Временный перезапуск plasmashell не завершает исполнитель. При замене
бинарника установщиком запускается новая версия исполнителя.

Необходимы Plasma, адрес D-Bus, Wayland/X11 display и реальные владельцы
сервисов KWin/plasmashell на этой шине. Фоновое событие не
устанавливает зависимости и не запрашивает пароль. Недостающие ресурсы нужно
установить вручную; результат виден в расписании и [аудите](APPLY_PROTECTION.md).
Обычные политики перезапуска приложений сохраняются; автоматический перезапуск
возможен только при уже выбранной политике `always`.

Удаление CLI удаляет его autostart-файл; правила остаются при `--only-cli`.
Повторная установка сама не включает расписание: включите его явно.

## Проверка

Изолированные Rust-тесты проверяют дни, границы времени, повтор локального
времени, сохранение правил, конфликты, отметку до применения и отсутствие
повторного запуска. Проверка в настоящей изолированной Plasma фиксируется
отдельно в карточке задачи; `KTM_THEME_NO_APPLY=1` не считается живой проверкой.

Живой smoke-тест: `tests/e2e/schedule-history.py` (только Docker). При недоступных
зеркалах можно использовать системные `/usr` и `/etc/fonts` в режиме read-only:

```sh
docker run --name ktm-priority-live --network=none --cap-add SYS_NICE --shm-size=512m \
  -e KTM_PRIORITY_CONTAINER=1 -v /usr:/usr:ro -v /etc/fonts:/etc/fonts:ro \
  -v "$PWD:/src:ro" ktm-dependencies python /src/tests/e2e/schedule-history.py
```

Это изолированная сессия с системными версиями Qt/Plasma, **не** проверка
установки на чистой машине. Конфиги, HOME, D-Bus и дисплей хоста не монтируются.
Тест запускает настоящий KWin/plasmashell, ждёт расписание при отсутствии GUI,
проверяет apply/историю/целостность бэкапа/восстановление и персональный ключ.
`KTM_COMMAND_TIMEOUT=15` ограничивает внешние команды теста; hooks не отключены.
Результат и журналы: `/tmp/ktm-priority-live/` внутри контейнера.

## Отображение GUI

Страницы истории/расписания используют те же поля и семантические цвета, что
остальное приложение. Состояния/источники и дни недели переводятся в GUI,
исходные коды остаются в данных Rust. Даты/время отображаются по локали. Ошибки
сохраняют полную диагностику. «Новое правило» сбрасывает поля формы к исходным
значениям; правила и их выполнение по-прежнему принадлежат Rust.

# Kolira: имена и совместимость

- Проект и отображаемое имя: **Kolira**. Каталог checkout может называться `kolira`.
- `kolira` — Rust CLI; `kolira-gui` — Python/QML GUI. Установщик и component-only
  uninstall работают с разными файлами и не заменяют/удаляют соседний компонент.
- Desktop entry: `kolira.desktop`, иконка: `kolira-icon.svg`, перевод: `kolira_ru.qm`.
- Данные: `$XDG_CONFIG_HOME/kolira`. Rust переносит данные из `kde-theme-profile`
  и `theme-profile`, включая `profiles` → `themes` и каталог палитры внутри снимка.
  Существующие файлы назначения не заменяются, конфликтующие источники остаются.
  Сохранённые абсолютные ссылки истории на перенесённые бэкапы разрешаются
  через новый каталог; отсутствующий бэкап остаётся видимой ошибкой.
- Новые пакеты: `kolira/theme@2`, экспорты: `kolira/export@1`. Загрузчики также
  принимают прежние `theme-profile/theme@2` и `theme-profile/export@1`; контрольные
  суммы и проверки безопасных путей обязательны для обоих форматов.
- Комплектные ресурсы переименованы вместе со ссылками; `export.json` пересчитан
  по фактическому содержимому. Новые файлы/ссылки не меняют живое оформление.
- Переменные `KTM_*` сохранены как совместимый контракт. Исторические сообщения
  и названия в отчётах не требуют механической замены.

Проверки: Rust-регрессии legacy import/data migration, все комплектные пакеты,
раздельная установка CLI/GUI в fake HOME, Python/QML и штатные линтеры.
Результаты: release build, 194 Rust / 336 Qt / 257 shell прошли, линтеры чистые,
893 finished-перевода, шесть комплектных экспортов без ошибок файлов/хешей.
[Карточка и границы проверки](../tasks/2026_11_09_kolira-rename.md).

Снимки со старыми `theme-profile.conf/.toml/.css/.omp.json` читаются под новыми
логическими именами через общий resolver; новые файлы имеют приоритет. Файлы
пользовательской темы для этого не переименовываются; preview и Apply используют
один resolver, включая привязку host-конфигов oh-my-posh/ghostty.

Определение компонентов старого снимка использует тот же resolver, что preview
и Apply: терминалы со старыми именами файлов учитываются и в отчёте/списке.

Для уже запущенных Kitty поддержаны сокеты `kitty-theme-profile[-PID]` наряду
с `kitty-kolira[-PID]`. После Apply перечитывается живой `kitty.conf` с новым
include, а прозрачность берётся из отдельного файла темы. Обнаружение старого
файла включает перепривязку host-конфигов Kitty/Alacritty к новому include.

# Расписание, аудит и агентский интерфейс

Приоритет пользователя: расписание, аудит 10 смен, MCP/инструкции.

## Контракт

- Rust хранит историю операций, источник (`cli/gui/mcp/schedule`), исходную тему,
  полный/частичный отчёт и связь с бэкапом. Повторное применение — отдельная запись.
- Оставляем 10 завершённых записей и все требующие восстановления. Бэкапы при
  очистке истории не удаляем. Восстановление завершённой операции — новая
  транзакция со страховочной копией текущего состояния.
- GUI показывает отдельные страницы истории и расписания. Успешный apply не
  вызывает всплывающего отчёта; ошибка содержит переход к истории.
- Фоновый исполнитель — `theme-profile schedule daemon`, XDG autostart в Plasma.
  Правила используют локальные часы и ISO-дни недели 1–7. Пропущенные события
  не догоняем. При повторном локальном времени событие выполняется один раз
  за локальную дату; смена зоны использует новое локальное время.
- Событие отмечаем до применения: после аварии автоматически не повторяем.
  При совпадении выбираем первое правило по ID, остальные получают пропуск.
  Занятый appearance lock означает пропуск, ручное применение не прерываем.
  Недостающие зависимости требуют ручного решения; фоновый процесс не запускает
  установку и не показывает скрытых запросов пароля.
- Правила сохраняются атомарно отдельно от результатов. Редактирование правила
  не теряет состояние выполняющегося события. Удалённая/переименованная тема
  даёт ошибку с исходным именем; автоматического переназначения нет.
- MCP вызывает тот же Rust API. Инструкции доставляются из kit; пользовательские
  изменения сохраняются, новая версия предоставляется отдельно при конфликте.

## Проверка

Изолированные HOME/XDG: история/лимит/повреждённые копии/восстановление;
управляемые часы расписания; MCP stdio из произвольного cwd; инструкции,
повторная доставка и сохранение пользовательских правок. Затем обязательные
Rust/Python/shell/QML проверки. Live Plasma проверяется отдельно и явно.

Реализация и проверка завершены в описанных границах. Все три карточки и индекс
обновлены вместе. [Отчёт](../docs/audits/2026_11_09_priority-validation.md):
190 Rust, 330 Qt/Python, 256 shell, линтеры/переводы и настоящая изолированная
Plasma. Клиентское обнаружение проверено локальным HTTP-приёмником без модели;
для вложенного Codex документирован root marker, Claude запускается из корня.
Визуальная приёмка и объединение параллельной UI-ветки — отдельная задача.

# Редизайн Kolira — план и сверка рабочего дерева

База `af10414`, ветка `ux/redesign-plan`, worktree `kolira-ux`. План и уточнения контрольного раунда согласованы. Основной маршрут — Мои темы → карточка или подробности → сводка → применение. Редактор открывается отдельно и сохраняет контекст при навигации.

Согласованный объём реализован. Итоговая матрица проверок приведена после хронологии.

## 1. Текущая архитектура

`gui/qt-app/src/__main__.py` загружает PySide6/Kirigami, QML и контроллеры. `src/core/cli_core.py` и `protocol.py` связывают GUI с `kolira core METHOD`. Rust отвечает за чтение и запись, определение компонентов, транзакции и внешние команды. Документированный API v1 и CLI сохраняются для существующих клиентов и MCP. Далее пути QML и Python относительно `gui/qt-app/`, Rust — относительно `gui/qt-app/src/core/rust_core/`.

## 2. Возможности для повторного использования

- Библиотека и метаданные: `profile.list/info/summaries`, `controllers/__init__.py`, `ProfileCardDelegate.qml`. Есть swatches и отпечаток оформления. `profile.preview` — план изменений и токен, отдельный от визуального превью.
- Apply использует `ApplyPreviewDialog.qml`, `CliProfileCore.preview/apply`, Rust `src/profile.rs`, `src/change_plan.rs`, `src/undo.rs`, `src/operation.rs`. Карточка, подробности, редактор, трей и будущая команда повторного применения из истории открывают одинаковую сводку. Восстановление из истории остаётся отдельной операцией. `src/schedule.rs` сохраняет автоматический вызов пакетного Apply и свою политику отсутствующих зависимостей. Внешний Wofi `src/bin/theme-menu.rs` вызывает низкоуровневое применение снимка, его область работ вынесена в контрольный раунд.
- Редактор: `ThemePage.qml`, `ThemeComponentsPage.qml`, `ThemeSectionFields.qml`, `ThemeFieldRow.qml`, `ThemeApplicationsPage.qml`, `AppConfigTree.qml`, `PalettePage.qml`. Переиспользовать контролы, палитру, регистрацию приложений, выбор ресурсов, внешние ссылки, диагностику и инструменты.
- Rust Inspector хранит staging, revision, Undo и копии. Python получает данные контроллера и отображает их. Существующие `inspector.*` сохраняются до отдельного решения о совместимости клиентов.
- `DependenciesPage.qml`, `AuditPage.qml`, `SchedulePage.qml`, `SettingsPage.qml`, `AutomationList.qml`, системный трей, управление обоями и команды next/prev/pick остаются доступны. Инвентарь действий перед миграцией включает импорт, экспорт, создание из системных ресурсов, дублирование, правку описания, открытие приложений и настроек, поиск тем приложений, действия follow-up и аппаратные/внешние ограничения.

## 3. Недостающие возможности

Библиотеке нужны поиск, адаптивная сетка, отдельные статусы чтения и достоверного совпадения с Live. Свотчи дают представление о палитре, но не о композиции окна. Нужны крупное превью и страница состава профиля. Сейчас сохранённые профили в Inspector доступны только для чтения. Часть Live действий действует сразу, а некоторые пути создания темы могут сначала применить staging. Требуются профили с собственными черновиками и отдельное сохранение Live + черновик без изменения системы. История операций и аварийные копии существуют, но библиотека именованных закрепляемых точек и независимые лимиты требуют отдельной работы в core.

UX-аудит по qt-ui-design: критический риск для нового сценария — подмена безопасного черновика немедленным действием. Предупреждения — отдельные входы в компоненты и приложения, плотные действия карточек, кастомная подложка/стилизация окна, принудительная стартовая палитра в `__main__.py`, риск потери фокуса при перезагрузке темы. Возможность — использовать уже доступные отпечатки профилей для наглядной галереи. Целевая среда Plasma 6, прямоугольное настольное окно с динамическим масштабом, мышь и клавиатура, текущие RU/EN переводы. Проверить длину строк, системные крупные шрифты, доступные имена, видимый фокус и состояние с текстом, узкое окно и дробный масштаб. Анимации наследуют настройки и используются для переходов, без собственной постоянной декоративной анимации.

При смене системной схемы сначала проверить обновление палитры на уже запущенном окне через `src/theme_controller.py`. Если нужен существующий reload, тестировать сохранение маршрута, фокуса и черновиков. Проверить системный Qt/Kirigami и поставляемый PySide6 на реальной Plasma.

## 5. Модели и взаимодействие

- Галерея использует ID темы, метаданные, доступность и отдельные состояния загрузки, ошибки, пустой библиотеки и пустого поиска. Пакетно читать лёгкую сводку и лениво загружать детали и ресурсы. Данные `active-profile` могут появляться при сохранении, создании и восстановлении. Для фактического совпадения нужно чтение Live в Rust, а для события «Последнее успешное применение» — успешная запись журнала, если она доступна. При нескольких кандидатах или неполном чтении показывать неопределённость. Повторное применение из трея доступно по тому же правилу, что из карточки, включая обнаруженный дрейф Live.
- Визуальное превью использует один композиционный шаблон с окном, панелью, выделением и контролами. На входе именованные роли палитры, доступные метаданные декорации, реальные образцы значков и обои. Текущий `swatches` отбрасывает пропуски и подходит для полосы цветов, но сдвигает роли при позиционном чтении. Расширение ответа должно сохранять пропуски по ролям. Добавить разрешение ресурсов через существующие правила Rust, нейтральные заглушки и пометку приблизительности. Ограничить кэш по ревизии профиля, отпечатку используемых ресурсов, версии рендера, размеру и DPR. Ограничить очередь видимыми карточками и размер декодирования. Проверить отсутствие Live-записей, сетевого поиска, сторонних исполняемых стилей и построения плана применения для каждой карточки.
- Черновик по источнику хранит базовую ревизию, исходную принадлежность поля, намерение «установить / исключить», текущее значение и конфликты. Rust сравнивает исходное, актуальное и предложенное значения. Незатронутое обновляется, совпавшая правка снимается, реальный конфликт даёт выбор. «Исключить» снимает управление полем, включая поля в смешанном файле. Действующая семантика старых пакетов сохраняется. При удалении или замене исходного профиля черновик остаётся доступен в текущей сессии, а запись по старой ревизии блокируется. Сброс категории использует идентификаторы группы. Переключение страниц сохраняет Rust-сессию, выход проверяет все источники.
- Профильное сохранение меняет собственный пакет атомарно. Live + черновик строится через виртуальный снимок под блокировкой с тем же нормализатором и проверкой, что и Apply. Метаданные компонентов, assets, генерация палитры, ограничения на пользовательские данные и целостность синхронизируются Rust. Zen пространства, вкладки и prefs.js остаются пользовательскими данными.
- Фоновые операции используют существующую очередь worker и durable jobs там, где они есть. UI отклоняет устаревшие ответы по ID запроса/ревизии, блокирует повторный запуск мутации, показывает прогресс и реальные частичные результаты. Таймаут транспорта проверяет ID операции и историю перед повтором.

## 6. Кандидаты на минимальные изменения API

Расширять API v1 добавочными возможностями после проверки используемых DTO. Имена методов согласовать по фактическому dispatcher, без изменения смысла существующих вызовов.

1. Пакетная сводка с достоверностью совпадения Live, присутствием полей и доступностью ресурсов. Выводить отсутствующее отдельно от ошибки чтения и недоступного ресурса. Файлы `src/gui_api.rs`, `src/status.rs`, `src/field.rs`, `src/theme.rs`, `src/bundle_view.rs`. Использовать данные `bundle.metadata` и пакетные `values` там, где они достоверны. Проекция `components` может подставлять `default` для Plasma, а `applications` сейчас пуста. Отдельно проверить реальное присутствие полей и состав приложений. Сохранить форму существующих API для внешних клиентов.
2. Источник и ревизия Inspector, трёхстороннее обновление, набор операций над полями с явным удалением, сохранение профиля и синтез Live + draft. Дополнить тот же Rust staging/планировщик. Не менять старую семантику записи для других клиентов незаметно. Мутации используют имеющийся внешний lock перед lock сессии.
3. Точки восстановления и долговечная запись Live Apply. Отдельный индекс точек поверх механизма резервных копий, полный ручной снимок, ограниченная автоматическая точка с метаданными состава. Привязка к ID, атомарная проверка и восстановление, закрепление, переименование, удаление и политика очистки. Данные истории и аварийные операции сохраняются независимо. Не использовать restore для пересчёта 1 → 2 → 1.
4. Подтверждённый GUI-токен описывает весь состав пакета, `keep_wallpaper`, `without_sync`, состояние Live и результат проверки ресурсов. При устаревании пересчитать сводку и запросить новое подтверждение. При недоступном компоненте ядро определяет допустимый fallback или объясняет блокировку. Установка зависимостей запускается из импорта или раздела зависимостей существующим job. Переход к зависимостям и возврат сохраняют идентификатор темы и опции. Следующее применение требует свежей сводки и явного действия пользователя.

## 7. Миграция экранов

Галерея и детали сначала соседствуют с действующим инспектором. Затем компоненты редактора переводятся по категориям с проверкой паритета. Импорт, зависимости, обои, автоматизация и история получают отдельные маршруты. Перед снятием старых маршрутов проверить переходы из трея, активацию из лаунчера, выход с черновиками, экспорт, ручные действия приложений, локализацию и доступность. Автоматизация и MCP сохраняют свои контракты.

`src/theme.rs::migrate` и команда `kolira migrate` нормализуют снимок и строят пакет прямо в исходной директории. Старый `theme-bundle.json` может содержать настройки компонентов и приложений, которые текущий пакетный маршрут не читает. Для GUI конвертировать рабочую копию под блокировкой, переносить представимые настройки и сообщать о непереносимых до публикации. Новые параметры формируются из снимка, установленные ресурсы могут понадобиться для упаковки уже указанных в снимке значений. Проверить отсутствие записей в Live, целостность, повтор миграции и совпадение применяемого состава. Публикация после валидации атомарна, при ошибке исходник остаётся доступен. Сводка и токен должны соответствовать тому содержимому, которое будет применено.

## 8. Риски

- В штатном переключении `profile.rs` откатывает предыдущие изменения через `undo.rs`, запоминает исходное состояние, накладывает целевой профиль и записывает изменения. Пропуск целого файла и пропуск ключа внутри существующего смешанного файла идут по разным правилам. Проверить явное исключение поля, в том числе внутри `kdeglobals`, GTK и конфигов приложений, чтобы при сохранении пакета оно действительно перестало управлять значением. Проверить внешний edit, `keep_wallpaper`, отключение follow-up и старые вызовы с выбором компонентов.
- Метки «активна», «совпадает», «применялась» не должны сливаться. Частичные профили могут совпадать одновременно. Сопоставление ограничивается поддерживаемыми параметрами, доступными для чтения.
- Вызовы Apply из редактора, трея, расписания и карточки не должны расходиться по guard/rollback. Live Apply и Restore требуют собственных проверок транзакции.
- Превью могут вводить в заблуждение и тормозить запуск. Использовать только подтверждённые ресурсы, отдельно помечать приблизительность, проверить нагрузку и cache invalidation.
- Очистка бэкапов не должна убирать данные незавершённых операций, закреплённые точки или blobs журнала профилей. Реестр точек отделяет запись о завершении от наличия копии.
- Runtime-перекраска с bundled Qt, гонки Live/расписания, замена профиля при импорте, старые пакеты/бэкапы, закрытие с работой в фоне и ошибки чтения проверяются отдельно.

## Grilling

Установленный `grilling` требует интервью по дереву решений. В предыдущем сеансе записано согласование шести решений и проверка зависимого пути миграции старых снимков после Q1. При возобновлении состоялась независимая сверка фактов по ядру и GUI. Ниже сохранены принятые решения и выделены два новых вопроса, которые выявило чтение кода.

### Уточнения, внесённые после разбора

1. **Частичность пакета и выбор компонентов независимы.** `src/bundle_view.rs:131` и `src/preview.rs` отвергают выбор подмножества для современных packages. Сохранение пропущенных полей относится к составу пакета и предыдущему journal, а не к фильтрации на экране Apply. По решению Q1 GUI всегда применяет весь заданный состав. Legacy selection не переносится в новый интерфейс. Старые снимки переводятся в пакетный формат до применения. Учесть существующий auto-apply on startup, который переигрывает тему из маркера.
2. **Save — отдельный контракт.** `src/profile.rs:2129` вызывает `split_live_hosts` (Kitty/Alacritty) и записывает active marker. `inspector_session.rs:500` в текущем сценарии применяет staged изменения перед сохранением. `src/constructor.rs` формирует оформление через Live. Для трёх путей нового редактора (save фактического Live, save Live + staged, update profile) переиспользовать capture/field validation/package build через временное представление и publish без Live write/marker/hooks. `src/agent.rs` даёт пример offline-сборки нового пакета, но не покрывает edit, все значения Kvantum и все generic поля. Сохранить существующие CLI/MCP операции; UI явно различает «создать» и «применить».
3. **Сравнение состояния и согласованность черновиков.** `profile.summaries` годится как метаданные и seed визуального превью, а не доказательство идентичности Live. Для точного статуса учитываем свойства, которыми профиль управляет, доступность ресурса и тип сравнения. Одного маркера и fingerprint карточки недостаточно. Хранить различие absent/explicit default/unreadable. Трёхсторонний rebase выполняется по смысловым значениям Rust, повторная проверка перед commit обязательна. Удаление из наследуемых/составных секций не должно возрождаться проекцией палитры или defaults.
4. **Точки восстановления и история.** `operation.rs:698–774` ограничивает индекс завершённых записей, при этом папки копий могут оставаться. Restore завершённой операции требует ID, манифеста и blobs. «Сохранить текущее» в Apply Preview сейчас создаёт обычную тему. Точки получают отдельный индекс с ID и видом, а операции — ссылку, допускающую истёкшую копию. Целостность, права, откат самого restore, соответствие active/journal и защита pending operations проверяются Rust. Удаление касается только идентифицированных управляемых точек. Никакой массовой очистки папки backups или apply-journal. По Q5 каталог точек начинается с нового формата без миграции старых копий. Существующий аварийный Recover сохраняется, как и история операций независимо от копий. Пагинация истории заменит пользовательский предел в 10 записей, с сохранением совместимости существующего API.
5. **Зависимости.** `share.rs` импортирует, возвращает зависимости и не применяет тему. `Main.qml` сейчас переиспользует install-диалог и после импорта, и при Apply. В этом обходе уже можно потерять `without_sync`, а `keepWallpaper` может сохраниться от прошлого preview при новом импорте. Развести сценарии. После установки обновлять статус, новую сводку инициировать явно, передавать полный набор её параметров. Core определяет блокирующую ошибку и допустимый fallback. `controllers/dependencies.py` и Rust durable jobs остаются владельцами прогресса и отмены. При миграции сохранить доступ к сведениям о системном пакете.
6. **Обои и превью.** Текущая модель — основной выбранный image wallpaper, вложенный файл и исходный путь. Сохраняем present/absent/keep, приватность экспорта, каталог и навигацию next/prev. Reader для превью современного пакета использует точный объявленный файл, а не «первый файл в wallpaper/». Действующий Apply имеет собственную fallback-семантику в `src/profile.rs:2681`. Расхождение при нескольких файлах — отдельный регрессионный тест, не обещание точного совпадения. Будущие типы представляются capability, без новой библиотеки или движков.
7. **Порядок включения.** Если shell сначала выбирает «Мои темы», сохранить старый переход к Inspector до замены всех действий. Замена редактирования по категориям не должна одновременно оставлять немедленную запись и staging для одного контрола. Старый Apply из трея и startup проверять наряду с новым путём. Исключить сетевой поиск resources во время рендера. Для больших операций сохранять ошибки по ID даже при закрытии страницы и смене темы приложения.
8. **Доказательства и границы.** В коде есть `preview.rs::returning_to_theme_without_configs_restores_user_baseline`, проверки поздних изменений и keep-wallpaper, `two_stage.rs::followup_write_failure_rolls_back_desktop_and_extension_files`, тесты расписания и живой Plasma harness. Предыдущий прогон на рабочем дереве дал 308 Rust и 260 shell. Это исторические данные, а не новый прогон на чистом HEAD. Этап 0 закрывает разницу и добавляет точную цепочку 1→2→3→1 и комбинации отсутствующих ресурсов. Для нового Live Apply обособить ошибку файловой транзакции от внешнего reload, успех не объявлять до результата Rust.

### Первый раунд решений владельца

- **Q1. Решение владельца.** Всегда применять весь состав темы. Частичные темы остаются частичными по содержимому. Старые снимки конвертировать в пакеты при необходимости.
- **Q2. Live Apply.** Валидируем весь черновик перед записью и откатываем затронутые данные при ошибке записи; ошибки внешнего обновления показываем как отдельный фактический результат ядра? Рекомендация: да. Ручные команды приложения остаются явными отдельными действиями.
- **Q3. Граница хранения черновика.** Сохраняем черновики по источникам до реального выхода, включая сворачивание в трей; при выходе ни один черновик не теряется без подтверждения, восстановления после перезапуска пока нет? Рекомендация: да.
- **Q4. Решение владельца.** Только системные настройки Qt. Убрать ручной выбор System/Light/Dark из SettingsPage.qml и принудительный glass; при миграции старые значения не должны переопределять системную палитру. Проверить наследование системного шрифта, QQC2/Kirigami и текущего системного стиля, включая обновление после Apply. Не менять внешний JSON API ради удаления контрола.
- **Q5. Решение владельца.** Новый каталог не импортирует старые точки. Для новых управляемых точек план остаётся с лимитами 20 записей и 2 ГБ и защитой закреплённых. По отдельному поручению локально удалены 109 транзакционных снимков завершённых и неиндексируемых операций. 3 снимка recovery_failed сохранены для аварийного восстановления. Записи истории, apply-journal, обычные копии файлов и бэкапы установки сохранены.

- **Q6. Ресурсы при сохранении профиля.** Сохраняем существующие assets, лицензии, источники, app_targets, кеши редакторов, параметры GTK и обои вне явно изменённых полей? Рекомендация: да. Пересчитываем только зависимые данные для изменённых полей, включая manifest и export metadata. Если выбранный ID ресурса недоступен, сохраняем его с предупреждением.

Q2, Q3 и Q6 приняты владельцем по записи предыдущего сеанса. Повторная проверка после ответа по Q1 закрыла зависимые вопросы о выборочном Apply и расписании. Для миграции найден существующий путь Rust. Контрольный раунд уточняет сохранность семантики при конвертации.

### Контрольный раунд после возобновления

Проверка фактов по ядру и интерфейсу подтвердила общую транзакцию Apply и восстановление по `apply-journal`. Она выявила расхождение маркировки `active-profile`, потерю семантики старого `theme-bundle.json` при конвертации, смещение ролей в `swatches`, разные правила повторного применения в карточке и трее, отдельный Quit мимо проверки черновиков и потерю `without_sync` в обходе зависимостей. Уточнения внесены в разделы 2–10. Явное исключение поля из частичного профиля освобождает его значение по требованиям задания. Для нового формата может понадобиться явное описание владения полем. Точное сопоставление Live учитывает только непустой проверяемый состав профиля. Невозможность прочитать поле или подтвердить ресурс даёт неполный результат сравнения.

- **Q7 согласован.** Внешний Wofi `theme-menu` сохраняет действующий маршрут. Трей Kolira входит в общий GUI Apply.

- **Q8 согласован.** Закреплённые точки считаются в общем лимите 2 ГБ и сохраняются при его исчерпании. Лимит 20 относится к незакреплённым. При переполнении удаляются старые незакреплённые. Если закреплённые занимают весь лимит, интерфейс объясняет недоступность новой точки. Автоматическая точка может быть пропущена с понятным статусом. Техническая страховочная копия для атомарного Apply/Restore и запись истории живут по отдельным правилам.

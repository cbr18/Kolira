# Kolira Quick Switch — план реализации

Ветка `feat/quick-switch`, база `d8a371a`. План согласован по grilling
(раунды 1–5, вопросы Q1–Q23).

**Статус: этапы 0–5 реализованы, этап 6 (живой прогон) впереди.**
Готово: `quick_switch.get|set|cards|prepare|set_hotkey` в ядре, отдельный
процесс `kolira-quick-switch`, слой layer-shell, карусель с тремя формами,
шейдер (`.frag` → `.qsb`), экраны закрытия/применения/раскрытия, pre-flight и
транзакция через существующий Rust, настройки в главном окне, хоткей, переводы.
Проверки: Rust 351, Python/Qt 360, shell 266, clippy/fmt/shellcheck чистые.
Осталось: живой прогон на Plasma (оверлей, клавиатура, два монитора, реальный
apply) и правки по его результатам.

## 1. Границы

**Делаем:** отдельный быстрый полноэкранный оверлей выбора и применения темы
для ежедневного использования.

**Не делаем:**

- не заменяем и не упрощаем основной GUI Kolira;
- не дублируем бизнес-логику: никаких записей `kwinrc`, `kdeglobals`,
  `plasmashellrc` и пакетов тем из QML/Python;
- не используем Electron, WebView, wofi, rofi;
- не перезапускаем приложения (Q16: молча пропускаем `restart_*`);
- не показываем выдуманный прогресс.

## 3. Проверенные факты об окружении

- Plasma 6.8.3, KWin 6.8.3, Wayland; PySide6 6.12.0 (Qt 6.12); системный Qt 6.12.
- `layer-shell-qt 6.8.3` работает с PySide6 6.12. Attached-тип требует
  `import org.kde.layershell 1.0 as LayerShell` — без алиаса движок отвечает
  «Non-existent attached object».
- Живая проба: fullscreen-поверхность на `LayerOverlay` мапится, рисуется и
  закрывается чисто (проверено скриншотами и логом).
- `qsb` есть: `/usr/lib/qt6/bin/qsb` (в PATH нет).
- Холодный старт: `kolira --version` 1.5 мс; `core profile.list` 98–202 мс;
  `core profile.summaries` 18 мс (1 тема), 41 мс (3), 310 мс (10);
  `core operation.list` 144 мс; Python + QML-движок 435–496 мс.
- `profile.apply` — один блокирующий вызов без канала прогресса; наблюдаемость
  только через `operation.list` и запись `$XDG_CONFIG_HOME/kolira/operations/<id>.json`.
- `MutationGuard` — `flock` на `appearance.lock`, `try_lock` без ожидания:
  вторая операция получает мгновенный отказ.
- Хоткей на этой машине: `.desktop` с `X-KDE-GlobalAccel-CommandShortcut=true`
  + группа `[services][<name>.desktop]` в `~/.config/kglobalshortcutsrc`.
  Занято: `Meta+Y` (theme-menu), `Meta+K` (voxtype-toggle), `Meta+N`, `Meta+X`,
  `Meta+Shift+N`.
- Настройка `global_hotkey` в `AppSettings` существует, но нигде не используется.

## 4. Архитектура

```text
kolira-quick-switch (отдельный процесс, PySide6)
├── QuickSwitchApp          запуск, watchdog, завершение
├── QuickSwitchController    данные тем, pre-flight, apply, этапы, ошибки
├── HostSurface              один layer-shell surface на монитор
├── ThemeCarousel            лента карточек, снэппинг в центр
├── ApplyTransition          закрывающая волна и затемнение
├── ApplyScreen              шейдер + реальные этапы
├── RevealTransition         раскрытие
└── QuickSwitch.qml          корень, состояния: выбор / применение / ошибка

Rust core (существующий)
├── quick_switch.get|set        настройки
├── quick_switch.cards          дешёвый список тем (палитра, без probe иконок)
├── quick_switch.set_hotkey     запись сочетания с бэкапом
├── profile.preview             pre-flight и preview_token
├── profile.apply               транзакция (как в главном GUI)
└── operation.list              реальные этапы
```

Транспорт — существующий: `subprocess` → `kolira core <METHOD>`, JSON на stdin,
один JSON-конверт на stdout. Второй транспорт не вводим.

### Почему отдельный процесс

Главный GUI держит single-instance сокет `QLocalServer("kolira")` и при втором
запуске просто поднимает своё окно. Quick Switch не должен ни запускать всё
приложение, ни поднимать чужое окно. Отдельный процесс обходит это и не
инициализирует трей, инспектор и реестр приложений.

Плата — холодный старт 0.45–0.5 с. Смягчается двухфазной загрузкой (§15)
и кэшем списка. Резидентный демон сознательно не делаем.

## 5. Контракты Rust

### 5.1. Настройки: `quick_switch.get|set`

Новый модуль `gui/qt-app/src/core/rust_core/src/quick_switch.rs` по образцу
`automation.rs`. Хранение — тот же `app-preferences.json`, отдельный top-level
объект, свой `preferences.lock`, атомарная запись через `gui_api::write_bytes`.

```json
"quick_switch": {
  "enabled": true,
  "hotkey": "Meta+K",
  "card_shape": "rounded",
  "card_scale": 1.0,
  "dim": 0.72,
  "glow": true,
  "animation_speed": "standard",
  "apply_animation": true,
  "reduced_motion": "system"
}
```

`card_shape` ∈ `rectangle|rounded|parallelogram`,
`animation_speed` ∈ `fast|standard|smooth`,
`reduced_motion` ∈ `system|on|off`.
Валидация своя (bool / string / number), потому что существующий
`settings.set` принимает только `bool|string|array<string>`.
Неизвестные ключи внутри объекта сохраняются. Главный GUI читает объект на
каждый доступ (как `automationItems`), поэтому не может затереть его
устаревшим снимком `AppSettings`.

### 5.2. Дешёвый список: `quick_switch.cards`

```json
{"themes": [
  {"name": "glass", "active": true, "accent": "#586d47",
   "swatches": ["#..."], "variant": "dark",
   "preview": "/abs/path/wallpaper.jpg", "preview_revision": "123-456",
   "has_preview": true}
]}
```

Читает только `theme.json` (палитра, variant, путь обоев) — без перебора
иконок и без `preview_image`. Цель: ≤ 30 мс на 10 тем. Если измерения покажут,
что вызов не нужен, шаг заменяется на `profile.summaries` с ленивой
догрузкой; решение фиксируется по факту замера, а не по плану.

### 5.3. Хоткей: `quick_switch.set_hotkey`

Валидирует сочетание (тот же синтаксис, что пишет KDE: `Meta+K`,
`Ctrl+Shift+T`), затем:

1. бэкап `~/.config/kglobalshortcutsrc` в `~/.config/kolira/backups/`;
2. `kwriteconfig6 --file kglobalshortcutsrc --group "services][<app>.desktop" --key _launch "<key>"`;
3. если ключ `Meta+K` и у `[services][voxtype-toggle.desktop]` было `Meta+K` —
   увести его на `Meta+Shift+K` (только в этом случае);
4. пустая строка/`none` — снять сочетание.

`theme-menu` не трогаем.

### 5.4. Не меняем

Никаких изменений в `preview.rs`, `operation.rs`, `theme.rs`, `undo.rs`.
Quick Switch вызывает те же методы, что и главный GUI.

## 6. Экран выбора

- Поверх рабочего стола: слой затемнения (по умолчанию 0.72) с мягкой
  виньеткой. Настоящий рабочий стол виден; захват не требуется.
- Карусель по центру монитора под курсором.
- Карточка: превью, название, палитра, индикатор активной темы, при нехватке
  ресурсов — компактный индикатор.
- Активная карточка: `scale 1.0`, непрозрачность 1, рамка 3 px со свечением
  (палитра темы). Соседние: `scale 0.94`, непрозрачность 0.55, рамка 1 px.
- Акцент интерфейса (рамка активной, свечение, подложка подписи) плавно
  переходит к палитре выбранной темы. Цвет берётся из `accent` темы,
  fallback: `swatches[0]` → системный акцент.
- Открытие: затемнение и элементы появляются плавно (200–350 мс).
- При открытии активной становится текущая тема (`profile.active`,
  при устаревании — `profile.live_matches`).

### 6.1. Управление

| Действие | Поведение |
|---|---|
| ← / → | шаг карусели, активная карточка с анимацией в центр |
| Enter | подтверждение → переход к применению |
| Esc | закрыть без изменений |
| Колесо | перемотка ленты |
| Клик | выбрать карточку |
| Двойной клик | применить |
| Ввод текста | фильтр по названию (появляется поле поиска) |

Выбор карточки не меняет систему. `SnapOneItem`, одна анимация перемещения
подсветки; без бесконечной перемотки в v1 (лента конечная).

## 7. Переход к применению

1. Выбранная карточка становится центральной, остальные исчезают.
2. По экрану расходится волна в цветах палитры.
3. Рабочий стол полностью закрывается чёрным (200–350 мс, Q21: standard 250 мс).
4. **Только после завершения закрывающей анимации** стартует `profile.apply`.

Изменение оформления не начинается во время закрытия: между кадрами
рабочий стол не должен «мигать».

## 8. Экран применения

- Полностью чёрный фон, поверх — один `ShaderEffect` (GLSL).
- Uniform'ы: `time`, `resolution`, `palette[4]`, `accent`, `intensity`,
  `transition`.
- Один качественный эффект: медленные светящиеся волны/аврора из палитры
  темы. Никаких заранее записанных видео и тысяч QML-объектов.
- В центре: название темы, под ним — шкала и короткая строка состояния.
- Шкала: 3 реальных этапа `preparing → applying → finished` из
  `operation.list` (опрос раз в 700 мс, только на время транзакции), внутри
  этапа — бегущий индикатор. Проценты не выдумываются.
- Ошибка: вместо «успешно» показывается состояние отката/ошибки и текст
  Rust; анимация успеха не проигрывается.

## 9. Завершение

1. Rust вернул `succeeded`: формы растворяются.
2. Чёрный раскрывается радиальной маской из центра (200–350 мс).
3. Пользователь видит рабочий стол с новым оформлением, оверлей закрывается.
4. `restart_*` не выполнялись — показываем короткую строку «Требуется
   перезапуск: …» только если Rust вернул `actions` (Q16: молча, поэтому
   строка не является обязательной; по умолчанию не показываем).

Plasma не перезапускаем ради эффекта. Не ждём неопределённо долго
подтверждения от сторонних приложений.

## 10. Формы карточек

Один компонент `ThemeCard` + один `CardShape` (геометрия), три режима:

| Форма | Ширина | Особенности |
|---|---|---|
| `rectangle` | 0.72 · H | прямые углы |
| `rounded` | 0.72 · H | радиус 18 px (масштабируется) |
| `parallelogram` | 0.80 · H | маска `QtQuick.Shapes`, сдвиг 18 % |

H = 0.60 · высота монитора. Все карточки одной высоты, вертикальные.
Контент (превью, текст) не наклоняется: у параллелограмма маска применяется
к слою картинки и подложке, а не к тексту. Рамка, свечение и область
взаимодействия берут ту же геометрию, что и маска.

Добавление четвёртой формы = один новый `ShapePath`, без правок карусели.

Новая карточка «Quick Switch» в `pages/SettingsPage.qml` перед карточкой
Actions: `Kirigami.Card` + `Kirigami.FormLayout`, как остальные.

| Настройка | Контрол |
|---|---|
| Включить Quick Switch | Switch |
| Горячая клавиша | TextField с валидацией + подсказка |
| Форма карточек | ComboBox + мини-превью формы |
| Размер карточек | ComboBox (80/100/120 %) |
| Затемнение фона | Slider |
| Свечение рамок | Switch |
| Скорость анимаций | ComboBox (быстро/стандартно/плавно) |
| Анимация применения | Switch |
| Уменьшенное движение | ComboBox (системно/вкл/выкл) |

Значения читаются контроллером на каждый доступ через `quick_switch.get`

меняем.

## 12. Горячая клавиша

1. `resources/kolira-quick-switch.desktop`: `NoDisplay=true`,
   `X-KDE-GlobalAccel-CommandShortcut=true`, `Exec=kolira-quick-switch`.
2. Установка в `~/.local/share/applications/` рядом с `kolira.desktop`.
3. Запись сочетания — `quick_switch.set_hotkey` (§5.3), с бэкапом.
4. Дефолт `Meta+K`, `voxtype-toggle` уводится на `Meta+Shift+K`.
5. При выключении галочки сочетание снимается (Q22).
6. Повторный вызов не создаёт второй экземпляр: проверка single-instance
   сокета Quick Switch (отдельное имя, не `kolira`); при повторном вызове
   активный оверлей закрывается (toggle) либо игнорируется — по факту
   проверки; по умолчанию toggle.

Глобальный перехват клавиатуры в обход Wayland не используется.

## 13. Мультимонитор

- Один `HostSurface` на каждый `QGuiApplication.screen()`.
- Карусель — на мониторе под курсором (`QGuiApplication.screenAt(QCursor.pos())`),
  остальные — только затемнение.
- Во время применения анимация идёт на всех поверхностях; раскрытие
  синхронно (общий контроллер времени).
- `screenAdded` / `screenRemoved` — пересоздание поверхностей.
- Дробное масштабирование: размеры в `QtQuick`-единицах, без абсолютных
  пикселей; проверка на 125/150 %.
- Блокировку экрана и защищённые интерфейсы не перекрываем: перед показом
  сверяемся с `LockedHint` logind и не стартуем.

## 14. Ошибки и безопасность

| Ситуация | Поведение |
|---|---|
| `Another appearance operation is running` | сообщение в оверлее, Esc закрывает, транзакция не трогается |
| Rust не ответил N секунд (watchdog, дефолт 20 с) | «Kolira не отвечает», Esc закрывает; через 45 с — аварийное закрытие |
| Ошибка применения | экран показывает ошибку и состояние отката, анимация успеха не проигрывается |
| `PREVIEW_STALE` | повторный pre-flight, затем новый `preview_token`; без авторетраев |
| Требуются зависимости/действия | видимый список + «Открыть Kolira»; оверлей закрывается, поднимается главный GUI |
| Нет layer-shell | внятная ошибка, обычный Kolira продолжает работать |
| Ошибка шейдера/нет GPU | упрощённая анимация (плавное изменение цвета) |
| Esc при выборе | закрыть без изменений |
| Esc при применении | игнорируется (Q9) |

Падение визуального процесса не влияет на транзакцию: она живёт в Rust,
запись операции остаётся, восстановление — существующими средствами Kolira.

## 15. Производительность

- Двухфазная загрузка: дешёвый `quick_switch.cards` (≤ 30 мс) → мгновенный
  скелет карусели; `profile.summaries` догружается для видимых карточек
  (18 мс/тема).
- Кэш списка: `$XDG_CACHE_HOME/kolira/quick-switch/cards.json` с ключом
  `theme.json` (mtime+size); обновление в фоне после показа.
- Превью обоев — существующие пути `wallpaperPreviewUrl`, без пережатия.
- Шейдер один, без QML-частиц; `layer.enabled` у оверлея выключается
  после закрытия (нет постоянной GPU-нагрузки).
- Цель: открытие ≤ 0.6 с в тёплом кэше, 60 FPS на переходах, без фризов.
- Резидентный процесс не делаем; если замеры покажут > 0.8 с — отдельная
  задача.

## 18. Риски

| Риск | Митигация |
|---|---|
| Панели Plasma окажутся выше `LayerOverlay` | первая же живая проба; при провале — `exclusionZone`/`scope` или правило KWin |
| `KeyboardInteractivityExclusive` не даёт фокус на KWin 6.8 | проверить на живой сессии до этапа 3 |
| Холодный старт 0.5–0.8 с | двухфазная загрузка, кэш; резидент — отдельная задача |
| `Meta+K` конфликт с voxtype-toggle | миграция при включении, бэкап `kglobalshortcutsrc` |
| Шейдер не компилируется на чужом GPU | fallback на упрощённую анимацию |
| Блокировка экрана / polkit | не стартуем при `LockedHint`; системные диалоги — только вне оверлея |
| `preview_token` устарел между выбором и применением | повторный pre-flight, без авторетраев |

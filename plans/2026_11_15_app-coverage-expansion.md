пометка в основной очереди, а не основание для P4.

## Цель и границы

При смене темы согласованное оформление получают выбранные пользователем
приложения. При возврате к теме без настроек этого приложения восстанавливается
исходное состояние с сохранением последующих личных правок. Поддержка означает
обнаружение → сохранение → preview → применение → возврат, а не наличие файла
с цветами. Отдельно обозначаем генерацию палитры и обновление открытого приложения.

Всё реализуется в едином Rust core; Python/QML только отображают возможности,
выбор и результат. Произвольные shell hooks не исполняются; операции адаптера
готовятся и проверяются в Rust.

Fastfetch, раскладка панелей/значок меню остаются исключёнными. SDDM, root-файлы,
LXQt/labwc не входят в эту очередь. Steam остаётся исключённым. Neovim включён
пользователем в P0 как установленный редактор: прежнее исключение снято.
Автономный адаптер Neovim реализован в первой партии; исторические DONE-чекбоксы
сами по себе не означают текущую поддержку.

## Этап 0. Контракт адаптера и общий план изменений

- Описать для каждого адаптера возможности: detect, capture, palette generation,
  выбор готовой темы, profile apply, restore и live reload. Показывать частичную
  поддержку явно; не объявлять установленный extension автоматически выбранным.
- Единое описание discovery и путей для CLI, реестра и GUI. Учитывать XDG,
  native/Flatpak, custom config path, несколько профилей/хранилищ. Не искать
  рекурсивно по всему HOME и не выполнять пользовательский Lua/Python ради
  обнаружения. Пути вне обычных контейнеров задаются/выбираются явно и проверяются.
- Ресурсы темы в namespace Kolira, личные hosts — только необходимые значения
  или включает. Preview перечисляет все файлы, создания, удаления, ключи, runtime
  действия и требования перезапуска. Чтение/discovery не создаёт каталогов.
- Profile apply использует общий `Plan`, `MutationGuard`, `operation::run` и
  before/after-журнал. Follow-up не пишет за пределами этого плана. Остальные
  точки входа используют ту же подготовку и защиту, без обходного writer.
- Выбор приложений явный: расширить валидируемый список app_targets по мере
  готовности адаптеров, defaults не расширять автоматически. Ресурс снимка
  имеет приоритет над генерацией; отсутствующее приложение пропускается с причиной.
- Недопустимый/неподдерживаемый host не заменять пустым или стандартным конфигом.
  Сохранять права, symlinks согласно контракту безопасных путей, комментарии и
  посторонние настройки. JSONC менять по позициям значений, TOML — с сохранением
  оформления; для вложенного YAML нужен отдельный сохраняющий структуру patcher.
- Не скачивать зависимости во время обычного Apply; отдельная подготовка через
  существующий реестр зависимостей. Не менять запуск/плагины редактора как
  незаявленную часть установки цветовой темы.

Результат этапа: таблица возможностей в коде и тесты единого плана; следующий
адаптер не добавляет независимый механизм записи или отката.

## Этап 2. Новые терминалы и TUI

Порядок небольшими партиями с отдельной проверкой каждого адаптера:

1. **tmux, Zellij, Starship**. Ресурс + активный host: `tmux.conf` source,
   `zellij/config.kdl` theme, `$STARSHIP_CONFIG`/`starship.toml` palette.
   Приоритет путей/inline colors определить до кода; не менять mouse, bindings,
   модули prompt, default-terminal. Для tmux отдельно проверить возврат live options.
2. **Foot, WezTerm, Rio**. Файл схемы + выбранная схема/include. Учитывать system
   config, custom paths и формы Lua. Сложный WezTerm Lua — явное подключение
   либо понятный отказ, не regex-перезапись произвольной программы.
3. **Helix, Micro, fzf, lazygit**. Для Helix/Micro выбирать имя темы; fzf —
   отдельный colors-файл и управляемое подключение без потери пользовательских
   FZF options. lazygit: только gui.theme, не перенастройка всего YAML.
4. LazyVim: расширение после автономного адаптера Neovim из P0. У пользователя
   LazyVim не обнаружен; не устанавливать plugin manager/base16 плагин и не
   менять чужие plugin specs. Ограничения нестандартных конфигов показывать явно.

Ориентиры путей — в карте файлов. Окончательные пути и namespace закрепляются
при реализации; effective config и его приоритет проверяются отдельно.

## Этап 3. Браузеры и дополнительные приложения

- **Qutebrowser**: generated colors.py + управляемый config-source; не выполнять
  config.py во время preview и не менять личную логику.
- **Chromium / Brave / Ungoogled Chromium**: отдельный адаптер theme extension,
  поддерживаемая установка/ручное первое подключение; никаких записей
  Preferences/Secure Preferences и восстановления личного профиля целиком.
  Установить реальные требования reload/restart, не обещать live по одному manifest.
- **Halloy/Senpai, Zathura/Sioyek, Rofi/Fuzzel/Walker, Feishin/Supersonic**:
  добавлять по конкретным адаптерам, с явным включением и проверкой возврата.
  Список кандидатов не означает обязательство реализовать их все.

## Этап 4. Отдельные исследования

Blender, LibreOffice, GIMP, Inkscape, Darktable, OBS, игровые и AI-приложения.
Сначала для каждого выяснить формат, версионные пути, storage native/Flatpak,
runtime и способ отменить только оформление. Blender userpref.blend и LibreOffice
unopkg затрагивают больше отдельных цветов: бинарный файл/registry нельзя
считать безопасным адаптером по одному шаблону. Steam остаётся исключённым до
отдельного решения. Системные login themes в этот этап не включены.

## Критерии готовности каждого адаптера

- Проверен semantic результат, а не только наличие строки в generated файле.
- `A → B → A`, `A → B → тема без конфига приложения`, 3 повторных цикла:
  восстанавливаются значения, отсутствие файлов/каталогов, права и ссылки.
- Поздние ручные значения и посторонние настройки переживают возврат; конфликты
  понятны в результате. Новые файлы темы удаляются только при безопасном владении.
- Отсутствующий, пустой, некорректный host, custom/system config, отсутствующее
  приложение, native/Flatpak, несколько профилей покрыты подходящими случаями.
- Preview совпадает с реально изменёнными файлами; failure/interruption rollback
  проходит через общий журнал; повторное применение не дописывает includes.
- Экспорт/импорт в другом HOME/XDG не переносит пути автора; explicit ресурсы
  снимка выигрывают у генерации. Apply не делает сетевых запросов подготовки.
- Проверка работающего приложения в изоляции подтверждает reload и возврат;
  ограничения или обязательный restart записаны в docs, GUI и результатах задачи.
- Обновлены THEMES/CURRENT_APP/PALETTE/GUI README по области изменения,
  CHANGELOG Unreleased, индекс задач. Обязательные проверки репозитория пройдены
  перед коммитом кода. Счётчики «поддерживается» растут после этой проверки.
